title: "x402 Agent Integration"
description: "Make automated Canton Coin payments from an agent or backend service using the canton-agent-wallet CLI and SDK."

An **agent** (or payer) is any client that calls x402-gated endpoints. When the server returns `402 Payment Required`, the agent creates a `TransferCommand` on the Canton ledger, attaches the payment proof, and retries — all automatically.

## Install

```bash
npm i -g canton-agent-wallet
```

Set the facilitator URL once (or pass `--relay-url` per command):

```bash
export CANTON_AGENT_RELAY_URL=https://<your-facilitator>
```

## CLI Commands

### Create a wallet

Generates an Ed25519 key pair, allocates a Canton party, and saves the wallet to `~/.canton-agent/wallet.json`.

```bash
canton-agent-wallet create
# wallet ready (canton:mainnet)
#   party:   my-agent::1220...
#   fund me: send CC to that party id, then run: canton-agent-wallet claim
#   keyfile: ~/.canton-agent/wallet.json  <- back it up
```

### Address

Print the party ID — use this to receive CC from a wallet or another agent.

```bash
canton-agent-wallet address
# my-agent::1220...
```

### Balance

```bash
canton-agent-wallet balance
# 12.3400000000 CC  (3 holdings)
```

### Claim

Accept incoming CC transfers (e.g. the initial funding from a wallet):

```bash
canton-agent-wallet claim
# claimed 1 incoming transfer(s)
```

### Pay

Fetch any URL, automatically paying any x402 `402` challenge:

```bash
canton-agent-wallet pay https://api.example.com/resource
```

The CLI handles the full flow: reads the nonce, creates the `TransferCommand`, retries with the payment proof.

### Withdraw

Send CC to any Canton party:

```bash
# Send a specific amount
canton-agent-wallet withdraw --to "recipient::1220..." --amount 5.0000000000

# Send full balance
canton-agent-wallet withdraw --to "recipient::1220..."
```

### Export / Import

Back up and restore the wallet key:

```bash
# Export (prints private key — store securely)
canton-agent-wallet export > my-agent.pem

# Import on a new machine
canton-agent-wallet import --relay-url https://<your-facilitator> --key-file my-agent.pem
```

## Environment Variables

| Variable | Description |
|---|---|
| `CANTON_AGENT_RELAY_URL` | Facilitator URL — required for `create`, `pay`, `import` |
| `CANTON_AGENT_NETWORK` | Canton network (default: `canton:testnet`) |
| `CANTON_AGENT_API_KEY` | API key if the facilitator requires one |

## SDK Usage

For programmatic use (e.g. embedding payments in a backend service):

```typescript
import { makePayingFetch, withdraw, RelayClient, ensureWallet } from "canton-agent-wallet";

// Onboard or restore wallet
const wallet = await ensureWallet({
  relayUrl:  process.env.CANTON_AGENT_RELAY_URL!,
  network:   "canton:mainnet",
  partyHint: "my-agent",
});

// Check balance
const relay = new RelayClient({ relayUrl: wallet.relayUrl });
const balance = await relay.balance(wallet.party);
console.log(balance.cc); // "12.3400000000"

// Pay any x402-gated URL
const payFetch = await makePayingFetch({ relayUrl: wallet.relayUrl, network: wallet.network });
const res = await payFetch("https://api.example.com/resource");

// Withdraw
await withdraw({ to: "recipient::1220...", amount: "5.0000000000" });
```

## How TransferCommand Creation Works

When the agent pays an x402-gated URL, it exercises `ExternalPartyAmuletRules_CreateTransferCommand` on the Canton ledger:

1. `POST /v2/interactive-submission/prepare` → gets `preparedTransactionHash`
2. Agent signs the hash with its Ed25519 key
3. `POST /v2/interactive-submission/execute` with the signature
4. Agent resolves the `transferCommandCid` from the resulting `updateId`
5. Retries the original request with `PAYMENT-SIGNATURE: <base64 PaymentPayload>`

The Canton ledger atomically moves CC from sender to receiver and archives the `TransferCommand` in a single transaction.

## First-Request Latency

The first payment after a cold start is slower than subsequent ones. SV Scan caches `AmuletRules` (5 min TTL) and `OpenMiningRound` (30 s TTL) — these caches are empty on startup, so the first request warms them. Subsequent payments typically complete in 10–25 seconds on Canton mainnet.
